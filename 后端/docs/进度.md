## 三、关键设计决策

### 3.1 三条安全红线（**已在代码中实现**）

| # | 红线 | 实现位置 |
|---|---|---|
| 1 | **取件码只对相关方明文** | `OrderService.toOrderView` + `MaskUtil.pickupCode(code, owner)` |

| 3 | **安全词不走 AI** | `AiService.SAFETY_WORDS` → 命中直接返回 `provider="guard"` |

### 3.2 修复了 v10 的"取件没地图"

**`GeoService.refreshOrderDistance`** 现在**同时回写坐标**：

```java
// ★ 回写坐标（COALESCE：只在原来为 null 时才写，不覆盖已有值）
if (st[0] != null || bd[0] != null) {
    orderMapper.backfillCoordinates(orderId, st[0], st[1], bd[0], bd[1]);
}
```

**SQL 用 `COALESCE`** 保证不覆盖已有值：

```sql
UPDATE orders
   SET station_lng = COALESCE(station_lng, #{stationLng}),
       building_lng = COALESCE(building_lng, #{buildingLng})
 WHERE id = #{orderId}
```

### 3.3 存储过程错误码映射

**MySQL 用 `SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'ALREADY_TAKEN'`**，
Spring 包装成 `DataAccessException`。

**`BizException.fromProcedure()`** 把 20 个错误码映射成中文：

| 错误码 | 中文提示 |
|---|---|
| `ALREADY_TAKEN` | 该订单已被接单或已失效 |
| `CANNOT_ACCEPT_OWN_ORDER` | 不能接自己发布的订单 |
| `INSUFFICIENT_BALANCE` | 余额不足 |
| `ALREADY_EVALUATED` | 该订单已评价过 |
| … | （共 20 个） |

### 3.4 双 AI 路由优先级

```
安全词 → 转人工（不走 AI）
查订单 → 本地查库（走脱敏视图）
其他  → ① Ollama（本地优先，数据不出内网）
       ② Coze（云兜底）
       ③ 规则库（保底，永远可用）
```

**并带 Redis 结果缓存**（相同问题 1 小时内复用）。
