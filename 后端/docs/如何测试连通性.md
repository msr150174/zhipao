# 如何测试「后端 ↔ 数据库 ↔ Redis」是否连通

> **前提**：你已完成
> ✅ `V1__init_schema.sql`（10 张表）
> ✅ `V2__atomic_procedures.sql`（6 个存储过程）
> 库名：**`xyzp`**
>
> **我已把 `application.yml` 的默认库名改成 `xyzp`**，不用再改。

---

## 第 0 步：确认 Redis 是否已安装

**这一步很重要** —— `SmsService` 和 `AiService` 都依赖 Redis，**没装会启动失败**。

### 检查 Redis

```bash
redis-cli ping
```

**期望输出**：`PONG`

**如果提示 `redis-cli 不是内部或外部命令`** → 说明没装。

### 装 Redis（Windows，二选一）

| 方式 | 说明 |
|---|---|
| **A. WSL**（推荐） | `wsl --install` 然后 `sudo apt install redis-server` |
| **B. Windows 原生版** | <https://github.com/tporadowski/redis/releases> 下载 zip 解压运行 `redis-server.exe` |
| **C. Docker** | `docker run -d -p 6379:6379 --name redis redis:7-alpine` |

### ⚠️ 如果暂时不想装 Redis

**可以临时禁用**（但短信和 AI 缓存会失效）：

**方法 1**：启动时排除自动配置

```bash
mvn spring-boot:run -Dspring-boot.run.arguments="--spring.autoconfigure.exclude=org.springframework.boot.autoconfigure.data.redis.RedisAutoConfiguration"
```

**方法 2**：改 `pom.xml` 注释掉 Redis 依赖（不推荐，代码会报错）

> **建议还是装一个** —— Redis 很小，且后面功能都依赖它。

## 第 1 步：确认 MySQL 账号密码

```bash
mysql -u root -p
```

登录后执行：

```sql
SHOW DATABASES LIKE 'xyzp';        -- 应该能看到 xyzp
USE xyzp;
SHOW TABLES;                        -- 期望 10 张表
```

**记住你的密码**，下一步要用。

---

## 第 2 步：配置连接

**方式 A：环境变量**（推荐，不改文件）

Windows PowerShell：

```powershell
$env:MYSQL_USER="root"
$env:MYSQL_PASSWORD="你的MySQL密码"
$env:MYSQL_DB="xyzp"
$env:REDIS_HOST="localhost"
$env:REDIS_PORT="6379"
```

Windows CMD：

```cmd
set MYSQL_USER=root
set MYSQL_PASSWORD=你的MySQL密码
set MYSQL_DB=xyzp
```

**方式 B：直接改 `application.yml`**

找到这几行，把默认值改成你的：

```yaml
url: jdbc:mysql://${MYSQL_HOST:localhost}:${MYSQL_PORT:3306}/${MYSQL_DB:xyzp}?...
username: ${MYSQL_USER:root}
password: ${MYSQL_PASSWORD:}      # ← 这里填密码
```

**⚠️ 如果 MySQL 密码是空的**（有些本地安装默认空密码），保持 `password:` 后面为空即可。

**关键最后一行**：`context path '/api'` ← 说明全局前缀生效了

### ❌ 常见启动失败

| 报错 | 原因 | 解决 |
|---|---|---|
| `Access denied for user 'root'@'localhost'` | 密码错 | 检查 `MYSQL_PASSWORD` |
| `Unknown database 'xyzp'` | 库名错 | 检查库是否叫 `xyzp` |
| `Unable to connect to Redis` | Redis 没启动 | 见第 0 步 |
| `Communications link failure` | MySQL 没启动 | 启动 MySQL 服务 |
| `Table 'xyzp.xxx' doesn't exist` | V1 没跑 | 重跑 `V1__init_schema.sql` |
| `Port 3000 was already in use` | 端口占用 | 改 `SERVER_PORT` 环境变量 |

## 第 4 步：一键健康检查（**最关键的验证**）

**打开浏览器或 curl**：

```bash
curl http://localhost:3000/api/health
```

### ✅ 期望返回

```json
{
  "code": 200,
  "msg": "ok",
  "data": {
    "status": "UP",
    "mysql": {
      "connected": true,
      "database": "xyzp",
      "version": "8.0.35",
      "driver": "MySQL Connector/J",
      "tables": 10,
      "stations": 7,
      "buildings": 8,
      "users": 0
    },
    "procedures": 6,
    "redis": { "connected": true },
    "ai": "local"
  }
}
```

### 🎯 逐项检查这张表

| 字段 | 期望值 | 不对说明什么 |
|---|---|---|
| `status` | `"UP"` | `DEGRADED` = MySQL 或 Redis 有问题 |
| `mysql.connected` | `true` | 连不上，看 `mysql.error` |
| `mysql.database` | **`"xyzp"`** | 库名不对 |
| **`mysql.tables`** | **`10`** | **少于 10 = V1 没跑全** |
| **`mysql.stations`** | **`7`** | **0 = 种子数据没插进去** |
| **`mysql.buildings`** | **`8`** | 同上 |
| **`procedures`** | **`6`** | **少于 6 = V2 没跑全** |
| `redis.connected` | `true` | Redis 没启动 |
| `ai` | `"local"` | 只有规则库（因为没配 AI 密钥） |

---

## 第 5 步：测试真实读写（登录）

健康检查只证明"能连上"，下面测"能写数据"。

### 5.1 微信登录（无需密钥）

```bash
curl -X POST http://localhost:3000/api/auth/wx-login \
  -H "Content-Type: application/json" \
  -d "{\"code\":\"test_code_001\"}"
```

**期望**：

```json
{
  "code": 200,
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "user": {
      "id": "a1b2c3d4e5f6...",
      "nickname": "同学",
      "creditScore": 60,
      "balance": 0,
      "isRunner": false
    }
  }
}
```

### 🎯 这一步同时验证了 3 件事

| 验证项 | 说明 |
|---|---|
| **数据库写入** | 新用户被 `INSERT INTO users` |
| **JWT 签发** | 返回了 `token` |
| **Redis** | token 的 jti 后续用于登出黑名单 |

### 🔍 去数据库确认

```sql
USE xyzp;
SELECT id, nickname, credit_score, balance, created_at 
  FROM users ORDER BY created_at DESC LIMIT 5;
```

**应该看到刚才创建的用户，`credit_score = 60`** ✅

### 5.2 用 token 查个人信息

把上一步的 `token` 复制进去：

```bash
curl http://localhost:3000/api/user/profile \
  -H "Authorization: Bearer 你的token"
```

**期望**：返回同一个用户（手机号/学号已脱敏）

**并且**：**这时再查 `/api/health`，`users` 应该从 0 变成 1** ✅

## 第 6 步：测试 Redis（验证验证码）

### 6.1 发验证码

```bash
curl -X POST http://localhost:3000/api/auth/sms/send \
  -H "Content-Type: application/json" \
  -d "{\"phone\":\"13800001234\"}"
```

**期望**：

```json
{
  "code": 200,
  "data": { "sent": true, "devMode": true }
}
```

**`devMode: true`** 说明短信密钥未配置 → **验证码打印到日志**。

### 6.2 去服务端控制台找验证码

**在 `mvn spring-boot:run` 的窗口里找这行**：

```
【开发模式】手机号 13800001234 的验证码为 654321（5 分钟内有效）
```

**记下这 6 位数。**

### 6.3 🎯 直接去 Redis 里看（**这才是真验证**）

```bash
redis-cli
> KEYS sms:*
1) "sms:code:13800001234"
2) "sms:limit:13800001234"
3) "sms:daily:13800001234:2026-10-12"

> GET sms:code:13800001234
"654321"

> TTL sms:code:13800001234
(integer) 287          # 剩余秒数，应小于 300

> TTL sms:limit:13800001234
(integer) 45           # 频控倒计时，应小于 60
```

**看到这些就证明 Redis 完全正常工作** ✅

### 6.4 用验证码登录

```bash
curl -X POST http://localhost:3000/api/auth/sms/login \
  -H "Content-Type: application/json" \
  -d "{\"phone\":\"13800001234\",\"code\":\"654321\"}"
```

**期望**：返回 token（新用户，昵称是 `同学1234`）

### 6.5 🎯 验证"一次性"

**再执行一次同样的登录**：

```bash
curl -X POST .../auth/sms/login -d "{\"phone\":\"13800001234\",\"code\":\"654321\"}"
```

**期望**：`"验证码错误或已过期"` ✅

**因为验证成功后立即从 Redis 删除了。**

---

## 第 7 步：测试存储过程（接单）

这一步验证 **6 个存储过程能被 Java 正确调用**。

### 7.1 需要两个用户

```bash
# 用户 A（发布方）
curl -X POST .../auth/wx-login -d "{\"code\":\"user_a\"}"
# 记下 tokenA

# 用户 B（跑腿员）
curl -X POST .../auth/wx-login -d "{\"code\":\"user_b\"}"
# 记下 tokenB
```

### 7.2 用户 A 发布订单

```bash
curl -X POST http://localhost:3000/api/orders \
  -H "Authorization: Bearer tokenA" \
  -H "Content-Type: application/json" \
  -d "{
    \"deliveryType\": 1,
    \"stationName\": \"菜鸟驿站(3号楼店)\",
    \"buildingName\": \"1号楼\",
    \"roomNo\": \"203\",
    \"pickupCodes\": [\"8-2-3021\"],
    \"packageSize\": 2,
    \"reward\": 5.00,
    \"deadline\": \"2026-12-31T23:59:59\",
    \"urgent\": false
  }"
```

**期望**：返回订单，`status: "WAITING_ACCEPT"`

### 🔍 去数据库看

```sql
SELECT order_no, status, station_name, building_name, 
       station_lng, building_lng, distance_meters
  FROM orders ORDER BY created_at DESC LIMIT 1;
```

**重点看 `station_lng` / `building_lng`** ——
因为种子里我给了坐标，**这里应该有值** ✅
（这正是修复"取件没地图"的关键）

### 7.3 用户 B 接单（**调用存储过程**）

```bash
curl -X POST http://localhost:3000/api/orders/{订单ID}/accept \
  -H "Authorization: Bearer tokenB"
```

**期望**：`status: "ACCEPTED"`，`runnerName` 已脱敏（如 `同*学`）

**这一步验证了 `accept_order_atomic` 存储过程** ✅

### 7.4 验证并发保护（**存储过程的核心价值**）

**再让用户 B 接一次同一单**：

```bash
curl -X POST .../orders/{同一个订单ID}/accept -H "Authorization: Bearer tokenB"
```

**期望**：`"该订单已被接单或已失效"` ✅

**这证明 CAS 条件更新生效了。**

## 📊 快速自检清单

把上面步骤跑一遍，逐项打勾：

### 连接层
- [ ] `curl /api/health` 返回 `status: "UP"`
- [ ] `mysql.tables` = **10**
- [ ] `mysql.stations` = **7**，`mysql.buildings` = **8**
- [ ] `procedures` = **6**
- [ ] `redis.connected` = **true**

### 写入层
- [ ] 微信登录返回 token
- [ ] `SELECT * FROM users` 能看到新用户，`credit_score = 60`
- [ ] 再查 `/api/health`，`users` 数量 +1

### Redis 层
- [ ] 发验证码后，`redis-cli KEYS sms:*` 有 3 个键
- [ ] `GET sms:code:13800001234` 能拿到 6 位码
- [ ] 用该码登录成功
- [ ] **重复用同一码 → 报"已过期"**（一次性生效）

### 存储过程层
- [ ] 发布订单成功，`orders` 表有数据
- [ ] **`station_lng` / `building_lng` 有值**（坐标回填生效）
- [ ] 接单成功（调用了 `accept_order_atomic`）
- [ ] **重复接单被拒**（CAS 生效）

### AI 层
- [ ] `curl /api/ai/providers` 返回 `"local"`
- [ ] 问"信用分怎么算" → `provider: "local"`
- [ ] 问"我要退款" → **`provider: "guard"`**（不走 AI）

## 🆘 出问题怎么办

| 现象 | 排查 |
|---|---|
| **起不来** | 看控制台第一段报错，对照第 3 步的表 |
| **health 里 tables < 10** | V1 没跑全，重跑 |
| **procedures < 6** | V2 没跑全，检查 `SHOW PROCEDURE STATUS` |
| **stations = 0** | 种子数据没插，手动跑 V1 最后的 INSERT |
| **接单报"操作失败"** | 看服务端日志的 SQL 错误，可能是存储过程参数不匹配 |
| **Redis 连不上** | `redis-cli ping` 确认 |

**把报错原文发我**，我帮你定位。

## 🔧 一键测试脚本（可选）

**保存为 `test-api.ps1`**：

```powershell
$base = "http://localhost:3000/api"

Write-Host "`n=== 1. 健康检查 ===" -ForegroundColor Cyan
$health = Invoke-RestMethod "$base/health"
$health.data | ConvertTo-Json -Depth 5

Write-Host "`n=== 2. 微信登录 ===" -ForegroundColor Cyan
$login = Invoke-RestMethod -Method Post "$base/auth/wx-login" `
  -ContentType "application/json" -Body '{"code":"test_001"}'
$token = $login.data.token
Write-Host "token: $($token.Substring(0,30))..."
Write-Host "用户: $($login.data.user.nickname) 信用分 $($login.data.user.creditScore)"

Write-Host "`n=== 3. 查个人信息 ===" -ForegroundColor Cyan
$profile = Invoke-RestMethod "$base/user/profile" -Headers @{Authorization="Bearer $token"}
$profile.data | ConvertTo-Json -Depth 3

Write-Host "`n=== 4. 发验证码 ===" -ForegroundColor Cyan
$sms = Invoke-RestMethod -Method Post "$base/auth/sms/send" `
  -ContentType "application/json" -Body '{"phone":"13800001234"}'
Write-Host "devMode: $($sms.data.devMode)  ← true 说明验证码在服务端日志里"

Write-Host "`n=== 5. AI 客服（规则库）===" -ForegroundColor Cyan
$ai = Invoke-RestMethod -Method Post "$base/ai/chat" `
  -Headers @{Authorization="Bearer $token"} `
  -ContentType "application/json" `
  -Body '{"messages":[{"role":"user","content":"信用分怎么算"}]}'
Write-Host "provider: $($ai.data.provider)"
Write-Host "回答: $($ai.data.text)"

Write-Host "`n=== 6. AI 安全词（应转人工）===" -ForegroundColor Cyan
$guard = Invoke-RestMethod -Method Post "$base/ai/chat" `
  -Headers @{Authorization="Bearer $token"} `
  -ContentType "application/json" `
  -Body '{"messages":[{"role":"user","content":"我要退款"}]}'
Write-Host "provider: $($guard.data.provider)  ← 期望 guard"

Write-Host "`n✅ 测试完成" -ForegroundColor Green
```

**运行**：

```powershell
powershell -ExecutionPolicy Bypass -File test-api.ps1
```
